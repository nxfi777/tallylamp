# Dashboard UX audit — 7 October 2026

Audited service commit `c60a41f`, using ux-laws and ux-review. **21 findings: eight P1 workflow failures and thirteen P2 issues.** This records the pre-change audit; source line references refer to that commit. See [implemented fixes and verification](IMPLEMENTATION.md) for the completed changes.

The desktop interface has a coherent, quiet visual system and mostly sensible action emphasis. The main weaknesses are more consequential than polish: mobile layouts hide essential controls, error states can claim that access was removed when it was not, and control ownership can contradict itself. The fleet also makes operators open individual browsers to learn which agent and task need attention.

## Job and visual target

**Job:** let an operator understand the browser fleet, intervene safely, and manage the sessions and people that can access it.

The arriving questions are: “What is running or blocked?”, “Who has the keyboard?”, “Which task needs me?”, “Can another browser fit?”, and “Who can still access these logins?” The current interface answers the first and capacity questions partially; controller identity, current task, and trustworthy access-state recovery need work.

This is a working/utility surface, with transactional access and credential flows. The visual target is the existing console pattern: stable navigation, compact operational summaries, nearby actions, explicit ownership and read-only/control states. No substantial redesign was implemented, so the skill permits using the established direction without new Mobbin or Dribbble research. Keep the current typography and restrained surfaces. Heavy-component spend: **zero**; this console needs clear task completion rather than spectacle.

Four principles drive the recommendations:

- **Jakob’s Law:** preserve familiar navigation, keyboard tab behavior, and honest action completion.
- **Fitts’s Law:** expose reachable controls and give touch interactions adequate hit areas.
- **Serial Position:** surface controller, task, exceptions, and usable browser actions before lower-value detail.
- **Tesler’s Law:** retain infrastructure and proxy complexity, but disclose it when relevant.

## Prioritized findings

P1 means an essential workflow becomes inaccessible, loses its result, or gives a misleading access/control outcome. P2 means significant friction, misleading information, or an accessibility/clarity defect. “Observed” means reproduced in the browser with the real assets and isolated synthetic responses. “Source” means confirmed in implementation but not exercised against a live backend.

### P1 — fix before relying on mobile operation or access recovery

Workers repeats the problem. The grid’s automatic minimum propagates the table’s minimum width into the shell. Use `minmax(0, 1fr)` and `min-width: 0` on grid children; contain scrolling within the table wrapper. Then verify real touch and keyboard scrolling, without widening the page. **F03. Dismissing an in-flight creation loses accountability and sometimes the only credential.** Observed: submit a delayed browser creation, press Escape, and wait. ## What to retain and how to sequence the work

Keep the calm desktop shell, clear New browser/Take control emphasis, persistent project context, relative timestamps, distinct destructive styling, and explicit warnings about guest access to all saved logins. The basic modal focus trap worked: Shift+Tab wrapped from the first field to Cancel, Tab returned to the first field, and the background was inert. New browser retained its entered name and inline error after a failed save. Pairing success names the browser and tells the operator to return to the extension and share a tab. Read-only access approval states who can read which browser, for how long, and how to revoke it.

**First, restore reliable operation:** F01–F08. These changes should be independently reviewable: mobile containment and request actions; pending-write lifecycle; explicit dataset failures; truthful logout/denial; controller reconciliation; keyboard tabs.

**Next, make the fleet answer the operational questions:** F09–F12 and F16. Compact rows/cards should connect browser, controller, current task, status and next action. Include unhealthy/queued/moving states without redefining them as stopped. This is a layout decision, not a lower-priority cosmetic fix.

**Then, finish the forms and completion states:** F13–F15, F17–F21. Reuse the successful inline-submit behavior; validate eligibility before offering options; fix text contrast and viewer fidelity.

The tradeoff is deliberate: keep complexity and access consequences available, but shorten the path for routine work. Do not bury the controlling agent or urgent request to achieve a cleaner screen. Keep confirmations for token replacement and irreversible deletion; do not add one to every reversible action. No component-library replacement is justified by this audit.

## Coverage, measurements and limits

The real `dashboard/index.html`, `app.js` and `app.css` were rendered in Chrome DevTools with synthetic, isolated API and viewer responses. All five main pages, browser detail, sign-in and pairing were inspected at **375×812, 768×1024 and 1440×900**. Actual viewport emulation was used because ordinary window resize bottoms out at 500px. The mobile layout expansion in F01 was measured, not mistaken for a successful narrow render.

| Agents / profiles / workers | Populated at three widths; empty at 375px; failed worker list; New agent modal; saved-profile actions inspected in source |
| Browser detail | Watch/control, two remote tabs, injected lease expiry, dark/light, settled watch effect and decoration disabled |

Snapshot Lighthouse accessibility scores were 95 for browser detail in both themes and 97 for the mobile access-success state. These are checkable axes, **not UX quality scores**. The tablist structure and success-text contrast failures are retained in `measurements.json`; fixture SEO/robots/agentic-browsing results were excluded as irrelevant to this authenticated console.

One local trace at 4× CPU and Fast 4G measured LCP **1,418ms**, CLS **0.00**, and LCP discovery/load delay **1,210ms**. This supports investigating the bootstrap dependency chain before optimizing image bytes. These are synthetic lab figures, not production measurements or representative viewer throughput. The delayed-state test separately injected 1.8s per API response; `/me` plus the parallel data phase explains roughly 3.6s of blank content.

Watch arrival is configured as a 1.6s CSS animation, plays once, and leaves a persistent glow; settled frames and disabling the overlay were exercised. The reduced-motion rules for the watch effect and loading sweep were inspected in source; an actual reduced-motion device session was not exercised. No hover flyouts were found that require the diagonal-pointer test.

No live browsers, sessions, logins or credentials were changed. The synthetic viewer proves dashboard state handling, not real remote pointer accuracy, reconnection throughput, guest redemption, host migration, or server-side permission enforcement. Native screen-reader use, real phone keyboards, production latency and a long-session leak trace remain follow-up checks. Conditional agent-principal navigation was excluded because ordinary dashboard login establishes an administrator session.
